# PageLingo 方案分析

> 对比浏览器内置翻译、第三方翻译插件与自研扩展，给出本场景下的推荐方案、技术选型与关键实现要点。

## 一、需求拆解

| 编号 | 需求              | 难度 | 关键点                  |
| -- | --------------- | -- | -------------------- |
| R1 | 全页翻译且不破坏布局      | 中  | 只替换文本节点，不重建 DOM      |
| R2 | 划词 / 悬停 / 段落翻译  | 中  | 选区 API + 事件委托 + 防抖缓存 |
| R3 | 代码、命令、术语、链接保持原文 | 高  | 节点分类 + 占位保护，是本工具核心差异 |
| R4 | 动态内容自动翻译        | 中  | MutationObserver     |
| R5 | 五语互译 + 自动检测     | 低  | 后端语言参数化              |
| R6 | 非技术用户友好         | 低  | 简洁 popup + 默认合理配置    |
| R7 | 开源可维护           | 低  | 模块化、无构建、注释清晰         |

## 二、三类方案对比

| 维度      | 浏览器内置翻译  | 第三方翻译插件        | 本扩展（PageLingo）    |
| ------- | -------- | -------------- | ----------------- |
| 费用      | 免费       | 部分免费、高级功能收费    | 免费、开源             |
| 全页翻译    | ✅ 优秀     | ✅ 优秀           | ✅ 良好              |
| 划词 / 悬停 | ❌ 基本没有   | ✅ 多数支持         | ✅ 支持              |
| 代码/命令保护 | ❌ 会误译代码  | ⚠️ 部分插件支持，程度不一 | ✅ 专门优化（GitHub 场景） |
| 术语/链接保护 | ❌ 无      | ⚠️ 有限          | ✅ 占位保护 + 链接开关     |
| 语言对灵活性  | ⚠️ 固定    | ✅ 灵活           | ✅ 五语自由互译          |
| 自定义引擎   | ❌        | ⚠️ 少数支持        | ✅ 三引擎可换           |
| 隐私可控    | ⚠️ 数据发厂商 | ⚠️ 走第三方服务器     | ✅ 自选后端，源码可审计      |
| 开源      | ❌ 闭源     | ❌ 多闭源          | ✅ 完全开源            |
| 安装门槛    | 零        | 应用商店           | 需开发者模式加载          |

**结论**：浏览器内置翻译适合「快速看懂整页大意」，但**无法保护代码与术语**，对 GitHub/AI 站点反而添乱；第三方插件功能全但**闭源、部分收费、数据经他人之手**。对于「开发者看 GitHub + AI 网站」这一细分场景，**自研扩展在代码/术语保护上是不可替代的**，且开源可控，适合长期维护与二次定制。

## 三、技术选型

| 项      | 选择                                | 理由                                     |
| ------ | --------------------------------- | -------------------------------------- |
| 扩展规范   | Chrome Extension **Manifest V3**  | 现行标准，兼容 Chrome/Edge/Brave 等 Chromium 系 |
| 语言     | 原生 JavaScript                     | 无构建步骤、无依赖、便于开源维护与审查                    |
| 翻译请求位置 | background Service Worker         | 规避页面 CSP，统一限流与错误处理                     |
| 翻译后端   | Google 免费接口（主）+ MyMemory（兜底）+ 自定义 | 免费、零密钥；后端抽象便于替换付费 API                  |
| 内容脚本组织 | `window.LinguaPage` 命名空间 + 按序加载   | MV3 内容脚本不支持原生 ES Module，用命名空间模块化       |
| 设置存储   | `chrome.storage.sync`             | 跨设备同步                                  |

## 四、关键实现要点

### 1. 只替换文本节点，保持布局

全页翻译用 `TreeWalker(SHOW_TEXT)` 收集文本节点，仅改 `node.nodeValue`，**不增删 DOM 元素**，从而保持原有盒模型与排版。译文长度变化只可能引起轻微换行。

### 2. 代码/命令/链接的「节点级」跳过

`classifier.js` 维护三类规则：

- **标签黑名单**：`pre` `code` `kbd` `samp` `var` `textarea` `svg` 等整块跳过；
- **class/id/role 启发式**：命中 `hljs`、`language-`、`blob-code`、`monaco` 等即跳过；
- **尊重网页标注**：`translate="no"`、`contenteditable` 一律不碰。  
  链接保护由 `skipLinks` 开关控制，对 `<a>` 的祖先链做跳过。

### 3. 术语/标识符的「token 级」占位保护

对逃过节点级跳过的行内内容，`protector.js` 用正则把 URL、邮箱、git SHA、版本号、数字单位、专业术语替换为控制字符占位符（如 `\x010\x01`），翻译后再还原。这样「`git clone https://...` 里的 `git clone`」这类混杂文本也能安全翻译其余部分。

### 4. 动态内容

`dynamic.js` 用 `MutationObserver(childList+subtree)` 监听新增节点，防抖 300ms 后批量翻译，并复用同一套「跳过 + 占位」逻辑，保证懒加载内容与初始内容规则一致。

### 5. 后台翻译与限流

翻译请求统一由 Service Worker 发起，Google 接口单次最多 30 条、每批间隔 200ms，MyMemory 单条 300ms 间隔，避免 429。

### 6. 还原机制

翻译时用数组记录 `{node, 原文}`，还原时遍历写回并重建 `WeakSet`，支持一键「还原原文」。

## 五、已知局限与规划

| 局限         | 说明                  | 规划                                           |
| ---------- | ------------------- | -------------------------------------------- |
| 免费接口稳定性    | 非官方接口可能限流/失效        | 支持自定义引擎；文档给出付费替换指引                           |
| Shadow DOM | 不翻译 shadow root 内内容 | 后续版本穿透处理                                     |
| 双语对照       | 无「原文+译文」并排模式        | 可作为下一步特性                                     |
| 上架         | 需开发者模式加载            | 可提交 Chrome Web Store（`<all_urls>` 权限需补充用途说明） |
